## この文書の位置づけ

詳細設計書「テスト・評価方針」を受け、単体テスト・結合テストで確認する項目を一覧にする。各項目の期待結果は設計書の記述を正とし、本書と設計書が食い違う場合は設計書に合わせて本書を直す。

### テストの区分

| 区分 | ID の頭 | 対象 | 実施方法 |
|---|---|---|---|
| 単体テスト | UT | 1つのモジュール・関数。DB・外部APIに依存しない純粋な計算と、DBを1つの部品として使う処理 | pytest / Vitest(自動) |
| 結合テスト(部品間) | IT | 本体の API → サービス → DB の通し、管理コマンド、画面 → API呼び出し(API は模擬) | pytest(TestClient + 試験用DB)/ Vitest(自動) |
| 結合テスト(業務シナリオ) | ST | 画面・本体・DB を実際につないだ業務の流れ | 手動(開発用 Docker Compose で起動し、ブラウザで操作) |

### 表の見方

- **根拠**: 設計書の節、または機能要件の ID(F-xx)。「詳細」は詳細設計書、「要件」は要件定義書。
- **自動テスト**: 既存のテストで確認しているかどうか。テスト名から判断したため、細部は該当テストで確かめること。
  - ✅ 既存テストあり(ファイル名を記載。`app/backend/tests/` などの共通部分は省略)
  - △ 一部のみ確認(足りない観点を記載)
  - ― 未作成(追加の候補)
- 気象API(Open-Meteo)はすべて模擬応答で確認する(CLAUDE.md の決まり)。
- 「現在時刻」は `fixed_now` などで固定して確認する。日時はすべて日本時間。
