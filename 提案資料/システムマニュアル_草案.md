## 1. このシステムでできること

本システムは、天気予報・曜日・祝日や行事日・特売の予定と過去の販売実績から、商品ごとの販売数を予測し、**生鮮の発注数**と**惣菜の時間帯別の製造数**を自動で提案します。

- 画面を開くだけで、最新の予測に基づく提案が表示されます(ボタンを押して予測を始める必要はありません)。
- 提案ごとに「なぜその数なのか」(天気・気温・降水、祝日・特売、前週同曜日の実績、在庫など)を同じ画面で確認できます。
- **最終的に数量を決めるのは担当者です。** 提案はそのまま承認することも、修正してから承認することもできます。システムが勝手に発注することはありません。
- 承認した発注は一覧にまとめて印刷でき、それを見ながら既存の発注システム・PDAに入力します。

| 部門 | システムが提案するもの | 担当者が行うこと |
|---|---|---|
| 青果・鮮魚 | 納品日ごとの発注数(日単位) | 提案を確認・修正・承認し、承認済みリストを見て発注システムへ入力 |
| 惣菜 | 対象日の時間帯ごとの製造数 | 前日に計画を承認し、当日朝に陳列残数を入力して見直す |

**MVP(今回の版)でできないこと**

| 項目 | 状況 |
|---|---|
| 既存の発注システム・PDAへの自動送信 | 対応していません。承認済み発注リストを見て手で入力してください(将来、ファイル出力を検討) |
| 予測と実績の比較画面 | メニューにはありますが「準備中」です |
| 値引きの判断、地域イベントの反映、相場の反映 | 対象外です |
| 利用者の追加・パスワード変更の画面 | ありません。研究室の担当者が登録します |
| スマートフォン・PDAでの利用 | 対象外です(事務所PCのブラウザで利用) |

利用者は「発注担当者」と「店長」の2種類です。発注担当者は所属する部門(青果・鮮魚・惣菜など)の情報だけを扱えます。

## 3. 1日の使い方(早わかり)

### 青果・鮮魚(発注)

| いつ | すること | 使う画面 |
|---|---|---|
| 発注の前(例: 閉店間際) | 当日のPOSを取り込む(任意。前日までの分は取り込み済みであること) | データ取込 |
| 発注の前 | 現在の在庫を取り込む、または手入力する | データ取込 / 在庫入力 |
| 発注するとき | 発注画面を開き、提案・根拠・警告を確認して承認(必要なら修正) | 発注 |
| 承認後 | 承認済み発注リストを印刷し、既存の発注システム・PDAへ入力 | 承認済み発注リスト |
| 発注締め時刻まで | 誤りに気づいたら承認を取り消して修正 | 発注 |

### 惣菜(製造計画)

| いつ | すること | 使う画面 |
|---|---|---|
| 前日 | 翌日の時間帯別の製造計画を確認し承認 | 製造計画 |
| 当日朝 | 売場の陳列残数を入力し、製造開始前の時間帯を見直す | 製造計画 |
| 各時間帯の製造開始時刻まで | その時間帯の承認・修正・取消 | 製造計画 |

### 不定期の作業

- 特売・チラシが決まったら登録する(予測に反映されます)。
- 店長は、土用の丑の日などの行事日をカレンダーに登録する。
- 商品の追加・入数の変更があったら、店長が商品マスタを取り込む。

## 4. ログイン・ログアウト

【画面写真】

1. ブラウザで接続先URLを開きます。
2. ログインIDとパスワードを入力し、「ログイン」を押します。
3. 青果・鮮魚の担当者は発注画面、惣菜の担当者は製造計画画面が開きます(両方に所属している場合と店長は発注画面)。

- 「ログインIDまたはパスワードが正しくありません。」と出た場合は、入力を確かめてやり直してください。
- 画面の左側のメニュー(サイドバー)から各画面へ移動します。上部に利用者名と所属部門(店長は「店長」)が表示されます。
- 作業が終わったら、サイドバー下の「ログアウト」を押してください。

## 5. 発注画面(生鮮)

【画面写真】

### 5.1 画面の見方

| 場所 | 内容 |
|---|---|
| 画面上部 | 「発注締め HH:MM まで」(この時刻が承認・取消の期限) |
| 絞り込み | 部門、対象日(納品日)、状態(すべて/未承認/承認済み/確定/期限切れ) |
| 鮮度表示 | 「予測作成 10/16 19:42、予報取得 19:40、在庫 19:30時点」のように、提案がいつのデータで作られたかを表示 |
| 再計算ボタン | 手動で予測をやり直す |
| 提案の表 | 1行1商品 |

対象日を指定しない場合は、商品ごとに「今から発注して間に合う最も早い納品日」の提案が表示されます(表の「納品日」列で確認できます)。

### 5.2 提案の表の列

| 列 | 内容 |
|---|---|
| 商品 | 商品名 |
| 納品日 | この発注が納品される日 |
| 提案数 | システムが提案する発注数(発注単位=入数の倍数)。未承認の行は入力欄になっていて修正できます |
| 予測値 | 納品日の予測販売数(小数第1位まで) |
| 天候 | 天気のアイコンと区分(晴れ・雨など)、気温、降水確率 |
| 祝日・特売 | 祝日・行事日・特売の対象日であればバッジを表示 |
| 前週同曜日 | 1週間前の同じ曜日の販売実績 |
| 在庫・発注残・持越見込 | 現在の在庫、すでに確定した未納品の発注、納品時に残っていると見込まれる数 |
| 状態 | 未承認・承認済み・確定・期限切れ |
| 警告 | データ不足などの注意(13章) |
| 差分 | 修正済み・承認済みの提案について、新しい計算結果が違う場合に「再計算: 45(+3) 採用」と表示 |
| 操作 | 承認・保存・取消などのボタン |

### 5.3 画面を開いたときの動き

- 画面を開くと、保存済みの提案がすぐに表示されます。
- データが更新されている(在庫やPOSの取込、特売の登録、予報の取得から3時間以上経過など)場合は、裏で予測をやり直し、終わると表示が自動で新しい提案に切り替わります。計算中は「最新の予測を計算中… (処理済み/全体)」と表示され、承認ボタンは押せません。
- 数量を入力している途中に新しい結果が届いた場合は、入力を消さないよう自動では切り替えず、「新しい計算結果があります。」と「反映する」ボタンを表示します。
- 担当者が修正した提案と承認済みの提案は、自動の再計算で数量が変わることはありません。新しい計算結果が違う場合は「差分」列に表示されるので、必要なら「採用」を押して置き換えます。

### 5.4 そのまま承認する

- **1件ずつ**: 行の「承認」を押します。
- **まとめて**: 承認したい行の「選択」にチェックを入れ、「一括承認」を押します。
  - 警告のある提案は一括承認できません(「警告があるため一括承認から除外しました」と表示されます)。1件ずつ内容を確かめて承認してください。
  - 画面を開いた後に数量が更新された提案も除外されます(「数量が更新されたため一括承認から除外しました」)。表示し直された数量を確認してから承認してください。
- 警告のある提案を1件ずつ承認すると、「在庫が取り込まれていません。このまま承認しますか?」などの確認が出ます。

### 5.5 数量を修正して承認する

1. 提案数の入力欄の数を変えます。その行の「承認」が「保存」に変わります。
2. 修正理由を選びます(天候判断/特売・売場都合/在庫差異/その他)。選ぶまで保存できません。補足(128文字以内)は任意です。
3. 「保存」を押します。
4. 保存した行の「承認」を押します。

修正前の数と修正理由は記録され、予測の改善に活用します。気になった点は補足欄に書いていただけると助かります。

### 5.6 承認を取り消す

発注締め時刻までは、承認済みの行の「取消」を押すと未承認に戻り、再び修正できます。締め時刻を過ぎた承認済みの提案は「確定」となり、変更できません。確定した発注は「発注残」として、次回以降の提案の計算に使われます。締め時刻までに承認されなかった提案は「期限切れ」として記録に残ります。

### 5.7 手動で再計算する

在庫を入れ直した直後など、すぐに最新の提案を見たいときは「再計算」を押します。修正済み・承認済みの提案は数量を変えず、差分として表示します。

## 6. 製造計画画面(惣菜)

【画面写真】

発注画面とほぼ同じ使い方です。違いは次の通りです。

| 項目 | 発注画面との違い |
|---|---|
| 行の単位 | 「商品×時間帯」(同じ商品が時間帯ごとに並ぶ) |
| 対象日の表示 | 画面上部に「MM/DD の製造計画」と表示 |
| 期限 | 時間帯ごとの「製造開始」時刻が承認・取消の期限(既定は各時間帯の1時間前) |
| 在庫の列 | 代わりに「陳列残数」の列 |
| 発注締め | 表示しません |

既定の時間帯は「開店〜11時、11〜14時、14〜17時、17時〜閉店」です(店長が設定で変更できます)。

### 6.1 前日: 翌日の計画を承認する

前日に画面を開くと、翌日の計画が表示されます(陳列残数0として計算)。内容を確認し、発注画面と同じ手順で承認・修正してください。

### 6.2 当日朝: 陳列残数を入力する

1. 画面上部の「陳列残数の入力」欄に、売場に残っている数を商品ごとに入力します(入力した商品だけが保存されます)。
2. 保存すると「陳列残数を保存しました(HH:MM 時点)」と表示され、製造開始前の時間帯が計算し直されます。
3. 陳列残数は、**保存した時刻の直後の時間帯**の製造数から差し引かれます。

> **注意(【確認事項】)**: 各時間帯の「製造開始」から「開始時刻」までの間(既定では各時間帯の直前1時間)に保存した陳列残数は、その時間帯の製造がすでに始まっているため、製造数に反映されません。売場を確認する時刻とのずれがないか、ヒアリングで確認させてください。

- 承認済みの時間帯は数量が変わらず、新しい計算結果が「差分」に表示されます。
- 同じ日に何度入力しても、最後に入力した値で計算します。

## 7. 承認済み発注リスト

【画面写真】

承認済み・確定の発注を、商品コード順に一覧表示します。既存の発注システム・PDAへ入力するときにご利用ください。

- 表示項目: 商品名、納品日、発注数、発注単位、状態(承認済み/確定)、承認者
- 絞り込み: 部門、対象日(指定しなければ当日以降のすべて)
- ブラウザの印刷機能(Ctrl+P)で、A4縦の印刷用レイアウトで印刷できます(メニューなどは印刷されません)。
- 「承認済み」の行は、発注締め時刻までは取り消される可能性があります。入力後に取り消した場合は、発注システム側も忘れずに直してください。

## 8. データ取込

【画面写真】

POS売上・在庫・廃棄のデータ(店長は商品マスタも)を、CSVファイルで取り込みます。

1. 「種類」(商品マスタ/POS売上/在庫/廃棄)と「部門」を選びます。
2. CSVファイルを選び、「取込」を押します。
3. 結果として、取り込んだ件数・スキップした件数・エラーの行(行番号と理由)が表示されます。
4. 画面下部に取込履歴が残ります。

**ご注意**

- ファイルの形式は「標準取込形式」です(付録)。文字コードは **UTF-8**、日付は **YYYY-MM-DD**(例: 2026-10-15)です。Excel で開いて保存し直すと形式が変わることがあるため、ご注意ください。
- 誤りのある行だけを飛ばして、残りは取り込みます。エラーの行は理由を見て直し、もう一度取り込んでください。
- 同じ日・同じ商品のデータを取り込み直すと、新しい内容で置き換わります(POS・廃棄は日付×商品、在庫は基準日時×商品の単位)。
- 1ファイルの上限は 50MB です。過去分は期間を分けて取り込んでください。
- 店舗のPOSから出力したファイルを標準取込形式に変える方法は、出力形式を確認したうえで研究室が用意します【確認事項】。

## 9. 在庫入力(生鮮)

【画面写真】

在庫のCSVが出力できない場合は、この画面で手入力します。

1. 部門を選ぶと商品の一覧が表示されます。前回の在庫数と基準日時も並んで表示されます。
2. 商品ごとに在庫数を入力し、「保存」を押します。
3. 基準日時は、変更しなければ保存した時点の現在時刻になります。過去の時点の在庫を入れる場合だけ変更してください(「現在時刻にする」で戻せます)。

> 発注する日の在庫が入っていないと、提案に「在庫未取込」の警告が付き、在庫0として計算されます(提案が多めになります)。発注の前に必ず在庫を入れてください。

## 10. 特売・チラシ

【画面写真】

特売・チラシの予定を登録すると、その期間の予測に反映されます。

- 登録: 商品、開始日、終了日、内容を入力して登録します。
- 一覧: 期間で絞り込めます。行ごとに編集・削除ができます。
- 登録・変更すると、次に発注画面・製造計画画面を開いたときに提案が計算し直されます。

## 11. カレンダー(店長のみ)

【画面写真】

月ごとに祝日・行事日を表示します。祝日は公開データ(内閣府)から登録済みです。

- 日付を選んで行事日(土用の丑の日、地域のお祭りの前日など、店舗にとって売れ方が変わる日)を登録・削除できます。
- 登録内容は予測に反映されます。

## 12. 設定(店長のみ)

【画面写真】

| 項目 | 既定値 | 内容 |
|---|---|---|
| 安全係数(部門別) | 1.1 | 予測に掛ける余裕の割合。欠品を減らしたい部門は大きく、廃棄を減らしたい部門は小さくします |
| 発注締め時刻(部門別) | 閉店時刻 | 生鮮の承認・取消の期限 |
| 納品時刻(部門別) | 開店時刻 | 生鮮の納品時刻。納品までに売れる分の計算に使います |
| 営業時間 | 10:00〜20:00 | 開店・閉店時刻 |
| 惣菜の時間帯の区切り | 開店・11・14・17時 | 時間帯の開始時をカンマ区切りで入力 |
| 製造開始時刻 | 各時間帯の1時間前 | 惣菜の承認・取消の期限 |
| 再計算の判定時間 | 3時間 | 予報の取得からこの時間がたつと、画面を開いたときに自動で計算し直します |

- 変更した項目だけが保存されます。変更すると提案が計算し直されます。
- 時間帯の区切りを変えると「時間帯別モデルの再学習が必要です」と表示されます。研究室の担当者にご連絡ください(再学習までは簡易な予測方法で提案します)。

## 13. 警告と表示の意味

| 表示 | 意味 | 計算の扱い | どうすればよいか |
|---|---|---|---|
| 在庫未取込 | 発注する日の在庫が入っていない | 在庫0として計算(提案が多めになる) | 在庫を取り込む・入力してから見直す。一括承認不可 |
| 販売実績なし | 新商品などで過去の販売データが無い | 予測0 | 経験をもとに数量を修正して承認。一括承認不可 |
| 気象データなし(ベースライン予測) | 天気予報が取得できなかった | 簡易な予測方法(前週同曜日)で計算 | 天気を考慮して必要なら修正。一括承認不可 |
| POS未更新 | 前日分のPOSが取り込まれていない | 取り込み済みの最新日までのデータで予測 | 前日分のPOSを取り込む |
| ベースライン予測(警告ではない) | AIの予測モデルが使えない状態 | 前週同曜日の実績を予測値とする | そのまま利用できます。気になる場合は研究室へ連絡 |

警告のある行は背景色が変わります。

## 14. 提案数の計算方法

### 14.1 生鮮の発注数

```
持越見込 = 在庫 + 発注残 − 納品までに売れる見込み (0未満は0。持越できない商品は0)
必要数   = 納品日の予測販売数 × 安全係数
発注数   = 必要数 − 持越見込 を、発注単位(入数)の倍数に切り上げ
```

計算例: 納品日の予測 42.3、安全係数 1.1、持越見込 8、入数 6
→ 42.3 × 1.1 = 46.53、46.53 − 8 = 38.53 → 6の倍数に切り上げて **42**

### 14.2 惣菜の製造数

```
製造数(時間帯) = 時間帯の予測販売数 × 安全係数 − 陳列残数 (0未満は0。整数に切り上げ)
```

陳列残数は、入力した時刻の直後の時間帯だけから差し引きます。

### 14.3 予測に使っている情報

商品、曜日、祝日・行事日・連休の何日目か、特売の有無、天気(天候・気温・降水)、前週同曜日の販売数、直近7日間の平均販売数。天気は Open-Meteo(無料の気象情報サービス)の予報を使います。

> 画面の天候欄には予報の降水確率(%)を表示しますが、予測の計算には当面「降水量」を使っています(学習用の過去データで降水確率が得られないため)。

## 15. 困ったときは(FAQ)

| 困りごと | 対処 |
|---|---|
| ログインできない | ID・パスワードを確かめてください。分からない場合は研究室の担当者へ連絡してください |
| 急にログイン画面に戻った | 最後の操作から3時間たつと自動でログアウトします。もう一度ログインしてください |
| 「計算中」のまま終わらない | しばらく待ってから画面を開き直してください。「最新の予測の計算に失敗しました」と出た場合は「再計算」を押し、それでも失敗する場合は表示された理由を添えて連絡してください。それまでの提案はそのまま使えます |
| 承認しようとしたら「数量が更新されました」と出た | 裏で計算し直されて数量が変わりました。表示し直された数量を確認してから承認してください |
| 承認を取り消せない | 発注締め時刻(惣菜は製造開始時刻)を過ぎて「確定」になっています。変更が必要な場合は、既存の発注システム側で対応してください |
| 一括承認で一部の商品が承認されない | 警告のある提案は一括承認から除外されます。1件ずつ確認して承認してください |
| 提案が明らかに多い | 「在庫未取込」の警告が無いか確認してください。在庫を入れると適正な数に計算し直されます |
| 取込でエラーが出る | エラー行の理由を確認してください。多いのは日付の形式(2026/10/15 ではなく 2026-10-15)、文字コード(UTF-8 で保存)、商品マスタに無い商品コードです |
| 「予測と実績の比較」が開けない | MVPでは準備中です |

**問い合わせ先**: 【要記入】(沼尾研究室 スーパーマーケットDX 担当者名・連絡方法・対応時間)

## 16. データの取り扱い

- お預かりする店舗のデータ(POS・在庫・廃棄など)は、店舗と合意した範囲に限り、研究室のAWS環境の中だけで扱います。研究室の外への持ち出しや、ソースコードの保管場所(GitHub)への保存はしません。
- 通信は暗号化(HTTPS)し、接続できる場所を研究室と協力店舗に限定します。
- パスワードは復元できない形(ハッシュ化)で保存します。
- 決済情報(カード情報など)は扱いません。
- 修正・承認の操作は、操作者と日時を記録します。

## 17. 付録: 取込ファイルの形式(標準取込形式)

共通: 文字コード UTF-8、カンマ区切り、1行目は見出し行。日付は YYYY-MM-DD、日時は YYYY-MM-DD HH:MM(日本時間)。

| 種類 | 列名 | 必須 | 例 | 説明 |
|---|---|---|---|---|
| 商品マスタ | product_code | ○ | VEG-001 | 商品コード |
| | product_name | ○ | キャベツ | 商品名 |
| | department_code | ○ | VEG | 部門コード |
| | order_unit | ○ | 6 | 発注単位(入数) |
| | lead_time_days | ○ | 1 | 発注から納品までの日数 |
| | can_carry_over | ○ | 1 | 翌日に持ち越せるか(1=可、0=不可) |
| | cost_price | | 98 | 原価(任意) |
| | selling_price | | 158 | 売価(任意) |
| POS売上 | sales_date | ○ | 2026-10-15 | 販売日 |
| | sales_time | | 10:23 | 販売時刻(空欄は1日の合計。惣菜は時刻つきが必要) |
| | product_code | ○ | VEG-001 | 商品コード |
| | quantity | ○ | 3 | 販売数 |
| 在庫 | based_at | ○ | 2026-10-15 19:30 | 在庫を数えた日時 |
| | product_code | ○ | VEG-001 | 商品コード |
| | quantity | ○ | 12 | 在庫数 |

- 商品マスタに無い商品、取込先の部門と違う商品、負の数量の行はエラーになります。
